# Plan: `experiments/`, one folder per paper experiment, every run fully logged

Date: 2026-09-30
Status: approved plan, updated with the owner's answers and a run schedule (Sec. 10) the same day; implementation under way (Phase 0 and scoring done; graph-builder fix pending, see Sec. 2 and the Sec. 11 progress log)

This plan is written to be handed to Sonnet implementation agents after context compression. Everything an agent needs is in here; nothing is "as discussed".

## 1. Context

LesionGlue (paper) is written; now the experiments must be run. The repo already contains the three systems (`nanounet` promptable segmenter, `lesionglue` graph-OT matcher, `segtrack` coupled pipeline) but no code that produces the paper's numbers: metrics differ from the paper's (per-class recall, edge P/R/F1, identity ceiling, patient-level bootstrap), several experiments (calibration, prompt-noise sweep, baselines, PanTrack) have no code at all, and earlier evaluation scripts (`segtrack/scripts/e2e_eval.py`) print to the console and drop raw data.

Goal: a new top-level project `experiments/` holding **one folder per experiment**. Each folder has one main file, `run.py`, that runs the experiment exactly as designed here (plain-language header on top), plus any side implementations that experiment needs (e.g. the Qahqaie and Di Veroli matchers) as sibling modules. Each run produces a self-contained **run directory** that records the exact command, where outputs went, and every per-lesion / per-patient number needed to redo any table or plot years later without rerunning anything.

- Decoders (`lesionglue/model/decode.py`, **the code is authoritative**; verified on 2026-09-30 to be identical in logic to the old `lesion-tracking` branch `fix/sinkhorn-merge-decode`, commit `fa78009`, which the monorepo contains as `6480b8c`): `dense` (sigmoid pair logits >= 0.5, ignores the plan), `sinkhorn` (row-normalise the Sinkhorn plan over real columns + dustbin; keep **every** cell with mass >= tau, so merges and splits are expressible), `hungarian` (strict 1-to-1 on -log plan, then the same tau cutoff). The **many-to-one rule is `sinkhorn`**. Do **not** implement an argmax "row-wise" decoder: with unit marginals a k-into-1 merge leaves each contributor only ~1/k on the shared column (rest on the dustbin), so per-row argmax drops merges already at k=2; that is exactly why `fa78009` replaced it. The paper's Method sentence ("each row's largest entry when it clears a probability threshold") and the Exp-6 "row-wise rule" wording are **out of date and must be reworded** to "every plan cell whose row-normalised mass clears tau" (Sec. 8 item 9). Merge recall is recoverable only while 1/k >= tau (k < 8 at tau 0.125).

## 4. The run record (`experiments/common.py`, ~120-150 LOC)

Every experiment calls `run = start_run(EXP, ap, args, inputs={...})` right after argparse and `run.finish(summary, tables)` at the end. **Run dir layout:**

```
<out-root>/<exp>/<run_id>/            # out-root default /nnunet_data/experiments ; run_id = YYYYMMDDTHHMMSSZ_<tag>
  command.txt        # line 1: command as typed (python + argv). line 2: fully-resolved command with EVERY flag explicit. plus cwd, git sha, dirty flag
  run.json           # provenance (below)
  log.txt            # tee of the stderr console (plain text, no ANSI): header, config table, progress-free status lines, summary
  results.json       # SOURCE OF TRUTH (schema below)
  <table>.csv        # one tidy CSV per table in results.json["tables"] (per_lesion.csv, per_patient.csv, ...)
  table.md           # paper-table-shaped summary in Markdown (numbers + CIs)
  artifacts/         # heavy stuff only: predicted masks, pair-score .npz, fold checkpoints. Never mirrored to git.
```
Mirror: after `finish`, copy everything except `artifacts/` to `experiments/results/<exp>/<run_id>/` and append one line to both `<out-root>/INDEX.jsonl` and `experiments/results/INDEX.jsonl` (`{exp, run_id, command, out_dir, mirror_dir, status, wall_sec, git_sha}`).

## 5. Shared scoring (`experiments/scoring.py`) - implements paper Sec. "What we measure"

Pure numpy/scipy, no torch, no Lightning. Definitions (write them as the module docstring):
- **Node supply** = the lesion set each side hands the matcher: `Lstar` (annotation) or `Lhat` (segmenter output). A predicted lesion is *identified with* an annotated lesion when their IoU > 0.1 (`IOU_HIT`); the best-overlap annotated lesion wins, ties/one-to-many are recorded, not hidden. Unmatched predicted nodes are **extra nodes** (they can steal links but are never scored as lesions).
- **Per-lesion, per-class recall** (one decision per lesion): unchanged BL lesion correct iff decoded to its annotated FU partner; disappeared BL lesion correct iff `u_b=1` (no link); newly appearing FU lesion correct iff `u_f=1`; merged BL lesion correct iff decoded to the FU lesion it merged into (per contributing lesion, not per event). Under `Lhat`, a lesion whose node is missing is counted **wrong** in its class and the same counts feed the ceiling.
- **Identity ceiling** per class: fraction of that class's lesions whose required nodes both exist (unchanged/merged: BL node and FU partner node found; disappeared: BL node found; new: FU node found). Equals 1 under `Lstar`. "Matcher's share of error" = ceiling - recall.
- **Edge P/R/F1**: treat `M` as a set of (annotated BL id, annotated FU id) edges over the whole bipartite graph; a predicted edge touching an extra node is a false positive; never report accuracy over candidates.
- **Reporting rule**: never quote one class alone (a matcher that leaves everything unmatched gets 1.0 on disappearance); `summary` always lists all four classes plus edge F1.
- Seg (per lesion): Dice, NSD@1 mm, detection = IoU > 0.1; **prompt drop** = Dice with prompt channel on minus zeroed. Reuse `nanounet.score.dice/iou/nsd`.

Public API (fix these names/signatures so parallel agents agree):
```python
@dataclass
class PairCase:            # one patient's scan pair; everything needed to score identity
    pid: str; bl_ids: list[int]; fu_ids: list[int]           # annotated lesion ids
    topology: dict[int, str]                                  # BL id -> UNCHANGED|DISAPPEARED|MERGED ; FU-only ids -> NEWLYAPPEARING
    links: set[tuple[int, int]]                               # annotated (bl_id, fu_id) edges
    found_bl: set[int]; found_fu: set[int]                    # annotated ids present in the node sets (== all under Lstar)
    pred_links: set[tuple[int, int]]                          # predicted M in annotated-id space
    unclear: set[int] = frozenset()                           # linking_unclear BL/FU ids (excluded from headline, kept for the sensitivity row)
def score_pair(c: PairCase) -> dict[str, int]                 # per class {ok, tot, ceil} + tp/fp/fn
def match_nodes(pred_inst, gt_inst, iou_hit=IOU_HIT) -> dict[int, int]   # predicted id -> annotated id (or absent)
def pooled(counts: list[dict]) -> dict                        # recall/ceiling/precision/recall/F1 from summed counts
def bootstrap(counts_by_patient: dict[str, dict], b=BOOTSTRAP_B, seed=BOOTSTRAP_SEED) -> dict[str, tuple[float, float, float]]  # patient-level, percentile 95
def paired_delta(a, b, ...)                                   # paired bootstrap of the difference on the same patients
def load_pairs(root, pids, *, include_unclear=False) -> dict[str, PairCase-inputs]   # dominant-img_id_fu pair per patient from meta CSVs
```
Validation (temporary script, then delete per R16): on the cached test graphs with the deployed checkpoint (`runs/v7_complete/last.ckpt`, hungarian, tau 0.125) the new class counts must equal `lesionglue.eval.report._add_graph` counts (`disappeared`, `newly_appeared`, `merge`, `tp/fp/fn`), and `lesionglue_eval --split test` must still print 0.9701 (57 graphs). Decoding itself is **not** reimplemented: `scoring.py` takes predicted pairs from `lesionglue.model.decode.decode_pairs` (`sinkhorn`, `hungarian`).

**Owner-accepted scoring definitions (2026-09-30).** (1) Unchanged/merged recall: a BL lesion is correct iff its annotated FU partner is among the decoded links of that lesion; extra links cost edge precision only (the old `_add_graph` demanded set equality; the two differ only when a decoder can output several links per row, i.e. `sinkhorn`). (2) Under `Lhat`, when several predicted lesions overlap one annotated lesion (IoU > 0.1) they all identify it (the lesion counts as found, any of them can carry the link); `node_overlaps` in `scoring.py` exposes the full overlap table. (3) `_add_graph` counts on the old graphs cannot equal `score_pair` for merged rows by construction (it credits "no link" because the target had no node); parity was shown for disappeared, new and tp/fp/fn on all 57 test graphs.

### exp01_segmentation (GPU)
Question: does the segmenter answer the point rather than the image, in the four cases deployment produces? Cases come from `--manifest experiments/exp00c_seg_eval_manifest/seg_eval_v1.json` (default) (`--tier`, `--sources`, `--max-cases-per-source N`, `--max-lesions-per-case`). Lesion instances: cc3d connected components of the binary GT (connectivity 26, as in `nanounet/data/valset/build.py`; note `nanounet.score` uses 18 for *predicted* components: keep each as is and record it in `definitions`). ### exp04_baselines (CPU) - reimplementation of two published matchers
Question: does an identity-fitted correspondence beat hand-set costs? Same 300 patients, same 5 folds as exp03, `Lstar`, same scoring code (`scoring.py`), per-class recall on **only the classes each method's formulation can express** (record `expressible_classes` per method; unexpressible classes are `null`, not 0). Ours is read from the exp03 run (`--ours-run RUN_DIR`); exp04 never retrains. Side modules `qahqaie.py`, `diveroli.py` (exp09 imports them). Neither paper releases code or hyperparameter values, so **hyperparameters are tuned nested inside the folds**: to score fold k, grid-search on the other four folds' patients (objective: macro-average of the four class recalls, never one class alone), apply to fold k, record the chosen values per fold in `results.json`. Inputs per patient (`Lstar`): annotated BL/FU lesion masks with ids; centroid (mm), volume, equivalent-sphere radius `r=(3V/4pi)^(1/3)`; BL centroid carried into the FU frame by the shipped propagation (`cog_propagated`, backend `original`), FU centroid `cog_fu`.
**Qahqaie et al. (ISBI 2026, arXiv 2602.09933) - `qahqaie.py`.** Cost `C_ij = c_geom_ij * (1 + w_J*(1 - tau_ij)) * (1 - w_S * s_ij)`, `c_geom_ij = ||x_i - x_j|| / (r_i + r_j)` (capped). Trust `tau_ij = (T_i+T_j)/2`, `T_l` = mean over the dilated lesion mask of `exp(-beta*|log J(x)|)` with `J` the deformation-field Jacobian determinant. Appearance `s_ij = (s_i+s_j)/2`, `s_l` = ZNCC of patches at the centroid, rescaled to [0,1]. Masses `a_i = vol_i/sum vol` (BL), `b_j` (FU). Solve `min <G,C> + lam*KL(G 1 || a) + mu*KL(G^T 1 || b) - eps*H(G)` by Sinkhorn-style scaling iterations (Chizat et al. 2018; numpy, matrices are ~15x15). Tumour-load prior `rho = sum vol_FU / sum vol_BL`: `rho>1` lowers `mu`, `rho<1` lowers `lam` (the paper gives no magnitudes: implement `mu_eff = mu*min(1,1/rho)`, `lam_eff = lam*min(1,rho)` and say so). Relative pruning: keep `(i,j)` if `G_ij >= tau_row * max_j G_ij` **or** `>= tau_col * max_i G_ij` (the paper's wording is ambiguous between or/and: add `combine in {or, and}` to the tuning grid). Because relative pruning always keeps each row's maximum, add an absolute mass floor `kappa` (fraction of `min(a_i,b_j)`) below which an entry is dropped, so that disappearing/new lesions are expressible (the paper does not say how; document as our completion). Events from degrees: out-degree 0 = disappearing, in-degree 0 = new, 1-1 = persistent, in-degree >=2 = merging, out-degree >=2 = splitting. **Available inputs decide the variant**: no deformation field or Jacobian exists on disk (Sec. 2), so the primary variant sets `w_J = 0` (the paper's own ablation: the UOT backbone alone reaches edge F1 0.863, appearance 0.867, Jacobian trust "minor"); ZNCC patches are taken at BL centroid in the BL image vs FU centroid in the FU image (no warp). **The registration-trust term is not used, in any variant** (owner decision 2026-09-30: no Jacobians, no re-registration): `w_J = 0`, so `tau_ij` and `beta` drop out; the paper (Methods, baselines) must say the Qahqaie baseline omits its registration-trust term because no deformation field is available for this data.
**Di Veroli et al. (Medical Image Analysis 2024, PDF `/nnunet_data/graph paper.pdf`; extends the MICCAI 2023 paper) - `diveroli.py`.** Exact rule (Sec. 3.1-3.3, Fig. 2a). Pairwise deformable registration puts both scans in one frame (first scan moving, second fixed); lesions are vertices, matchings are edges. **Matching = iterative greedy overlap with three parameters** `d` (dilation, voxels), `p` (intersection threshold), `r` (iterations). Repeat `r` times: (1) dilate the remaining BL-frame lesion masks and remaining FU lesion masks by `d` voxels (integer voxels of the grid, not mm; structuring element unstated: use scipy's default cross, `binary_dilation(iterations=d)`); (2) for every remaining (BL, FU) pair compute `overlap = max(|A∩B|/|A|, |A∩B|/|B|)` on the dilated masks; (3) add edge (i,j) if `overlap >= p`, all pairs that clear `p` in the same iteration are added (so merges and splits arise when several lesions clear `p` together); (4) remove every lesion that received an edge from the remaining sets. **Reading forced by a gap (owner has no appendix; the pair-of-scans version, Rochman et al., IJCARS 2024, is paywalled as well):** the pseudo-code (Table A1) is in an appendix that is not in the PDF, so dilation is applied **cumulatively** to the still-unmatched lesions (iteration k has grown them by `k*d` voxels); this is the only reading under which `r` matters (with a fixed dilation every iteration sees the same overlaps, so nothing new could match); say so in the docstring and in the paper. Published values: `d=1`, `p=10 %`, `r=5/7/10` for lung/liver/brain. The 1.5-year rule belongs to non-consecutive matching (N>=3 scans): unused. **Classes from degrees** (Fig. 2a: Lone (0,0), New (0,1), Disappeared (1,0), Persistent (1,1), Merged (>=2, 0/1), Split (0/1, >=2), Complex (>=2,>=2) for (d_in, d_out); the paper sets `d_in=1` for first-scan and `d_out=1` for last-scan lesions): with two scans a BL lesion has `d_in=1`, so `d_out=0` Disappeared, `1` Persistent, `>=2` Split; an FU lesion has `d_out=1`, so `d_in=0` New, `1` Persistent, `>=2` Merged; Lone and Complex cannot arise. The paper drops lesions < 20 voxels or < 3 mm from its ground truth; we do **not** filter (every annotated lesion is scored for every method) and say so. Report **two rows**: (a) published parameters `d=1, p=0.10, r=7` (middle published value; r=5 and r=10 in a sensitivity table); (b) nested-tuned over `d in {1,2}, p in {0.05,0.10,0.20,0.30}, r in {3,5,7,10,15}` (published values lie inside the grid). Registration input: primary = **point-propagated masks** (translate each BL mask by `cog_propagated - cog_bl`, the same propagation as ours and Kirchhoff, no field needed); secondary = the **uniGradICON-warped BL masks** on disk (`derivatives/unigrad-icon-registration/{train,test}/targetsTrBL`, FU space; 292 of 300 patients, the other 8 scored as missed and listed). Organ masks are used by the paper only inside registration: not needed.
Output: per-patient counts per method x class (ok/tot), edge P/R/F1, chosen hyperparameters per fold, edge lists in `artifacts/`; summary with patient-bootstrap CIs and paired deltas vs ours.
